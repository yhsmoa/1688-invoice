## 1. 목표

경영자가 매일 아침 한 화면에서 아래를 보고 인원·우선순위를 정할 수 있게 한다.

| 질문 | 화면 표현 |
|---|---|
| 앞으로 들어올 물량이 얼마나, 언제 오나 | 1688 주문했지만 아직 입고 안 된 물량 → 날짜별 예상 입고량 |
| 들어와 있는 물량이 얼마나, 얼마나 기다렸나 | 입고됐지만 포장 안 된 물량 → 대기 일수 분포 |
| 처리해야 될 물량이 얼마나 되나 | 위 둘의 합 + 포장됐지만 출고 안 된 물량 |

## 2. 용어 — 파이프라인 5단계

PROCESSING 상태인 주문 항목(ft_order_items)의 수량을 아래 다섯 칸으로 나눈다. 한 항목의 수량이 여러 칸에 걸칠 수 있다(일부 입고 등).

```
[1688 주문 → 미발송] → [배송중] → [배송완료·입고 대기] → [입고 완료·포장 대기] → [포장 완료·출고 대기]
└──────── 앞으로 들어올 물량 ────────┘   └── 들어와 있는 물량 ──┘   └── 출고만 남음 ──┘
```

| 칸 | 수량 계산 (항목 단위) | 판정 근거 |
|---|---|---|
| ① 미발송 | 주문수량 − 입고 − 취소반품 | 배송이력 `shipped_seen_at` 없음 |
| ② 배송중 | 〃 | `shipped_seen_at` 있고 `delivered_seen_at` 없음 |
| ③ 배송완료·입고 대기 | 〃 | `delivered_seen_at` 있음 |
| (이력 없음) | 〃 | `im_1688_delivery_history` 에 주문 없음 (CSV 업로드 전) |
| ④ 입고 완료·포장 대기 | 입고 − 포장 | `ft_fulfillment_inbounds` ARRIVAL 합 − `ft_fulfillment_outbounds` PACKED 합 |
| ⑤ 포장 완료·출고 대기 | 포장 − 출고 | PACKED 합 − `ft_shipment_details` 합 |

- 입고량은 반드시 `ft_fulfillment_inbounds`에서 센다. `ft_order_items.arrival_qty`는 운영에서 전부 0이라 쓸 수 없다(확인됨).
- 배송이력은 CSV 업로드로 쌓이며 2026-08-26부터 있다.
- 취소반품은 ①~③에서만 차감한다. 입고 후 반품은 ④에 영향을 주지 않는다.
- **"앞으로 들어올 물량"은 이미 1688에 주문한 것만이다.** 앞으로 새로 주문할 분량은 포함되지 않는다. 1688 주문은 며칠에 한 번 몰아서 하므로(10-25 3,054개, 10-27 1,245개) 큰 주문 직후가 가장 정확하다.

## 3. 예측 모델

### 3-1. 유입 예측 — 앞으로 들어올 물량이 언제 오나

최근 8주에 입고된 건의 소요일 분포를 칸마다 따로 쓴다 (주문→입고 12,786건 · 발송→입고 8,953건 · 배송완료→입고 11,660건).
주문→입고: 평균 7.5일, 중앙값 7.0, 7일 내 51%, 10일 내 85%, 14일 내 98%.

```
P(d일째 입고 | 이미 a일 지남) = hist[d] / Σ_{k ≥ a} hist[k]
예상 입고[오늘 + (d − a)] += 남은수량 × P
```

- 표본 200건 미만인 분포는 주문→입고 전체 분포로 대체. 이력 없는 항목은 주문 항목 생성일 기준.
- 분포 밖이거나 14일 안에 안 올 몫은 "지연"으로 따로 표시하고 시뮬레이션에 넣지 않는다.
- 고객 장바구니(`ft_cart_items`)는 상태 값이 없어 유입 신호로 쓰지 않는다.

### 3-2. 처리 능력 — 최근 28일 실측

근무일 = 근무기록이 있고 스캔(입고행 + 포장행)이 1건 이상인 날. 근무시간 분모는 **전체 / 포장+검수** 토글.

| 지표 | 값 (전체 기준) |
|---|---|
| 하루 평균 인원 | 12.5명, 인당 7.6시간 |
| **라인/인시** (입고행 + 포장행, 근무일 중앙값) | **8.1** |
| 하루 평균 처리 | 761라인 (입고 427행 + 포장 334행), 포장 1,388개 |

"라인" = 스캔 행 수. 노동은 수량이 아니라 행 수에 비례한다(1행 20개도 스캔은 한 번).

### 3-3. 따라잡기 시뮬레이션 (사용자 결정 반영 — "목표 일수"가 아니라 "지금 인원이면 며칠")

```
하루 처리 라인 = 인원 × 인당 근무시간 × 라인/인시          (기본값 = 실측, 화면에서 수정 가능)
오늘부터 하루씩: 대기열 += 그날 예상 입고 행 × 2 (입고 스캔 + 포장)
               근무일(월~토)이면 대기열 −= 하루 처리 라인
처리 후 대기열이 0 이 되는 첫 근무일 = 따라잡은 날
14일 안에 못 따라잡으면 "못 따라잡음" — 하루 처리 < 하루 유입이라 밀림이 늘어나는 상태
하루 여유 = 하루 처리 라인 − 하루 유입 라인(14일 근무일 평균)
```

인원별 비교표(지금 −3 ~ +4명)로 "몇 명 더 뽑으면 며칠 당겨지나"를 바로 본다. 2026-10-30 기준 결과:

| 인원 | 하루 처리 | 하루 여유 | 따라잡기까지 |
|---|---|---|---|
| 9명 | 554 | +314 | 6 근무일 |
| 10명 | 616 | +376 | 4 근무일 |
| 12명 (지금) | 739 | +499 | 2 근무일 |

출고(쉽먼트)는 출고일(화·목)에 몰리므로 라인에 넣지 않는다.

## 4. 화면 — `/db/volume` 세 번째 탭 [물량예측] (`?tab=forecast`)

A. **지금 파이프라인** — 칸별 카드(수량 + 행 수), "앞으로 들어올 물량" 합계, "들어와 있는 물량" 카드에 대기 일수 막대(7일+ 빨강), 출고 대기.
B. **지금 인원·속도면 며칠 걸리나** — 근무시간 분모 토글(전체 / 포장+검수), 입력 3개(인원 · 인당 근무 · 처리속도, [실측값으로] 복원), 실측 카드 4장 + 따라잡기 카드(못 따라잡으면 빨강), 인원별 비교표.
C. **앞으로 14일 예상 입고** — 날짜별 행·수량·누적, 일요일 회색, 마지막 줄 "14일 뒤 또는 지연".
D. **확인 필요** — 배송완료 추정 후 7일 넘게 입고 스캔이 한 건도 없는 항목(사업자·주문번호·품번·상품·수량·배송완료 추정·경과).

배송상황 업로드가 2일 넘게 끊기면 경고 띠(처리속도 탭과 동일). 사업자별 보기는 넣지 않음(결정 2).

## 6. 엣지 케이스 (구현에 반영)

- 주문수량 < 입고(초과 입고): 남은수량 0. 포장 > 입고(입고 스캔 없이 포장): ④ 0으로 자르고 `inconsistent` 건수를 안내 문구에 표시.
- 소요일 분포 표본 200건 미만 → 주문→입고 분포로 대체. 90일 넘은 미입고는 90일로 묶는다.
- 일요일은 휴무로 보고 처리하지 않지만 유입은 쌓인다(월요일에 처리). 공휴일 달력은 범위 밖.
- 입력값이 0·빈칸이면 따라잡기 카드에 "입력값을 확인하세요".
